## 国内访问到底多少延迟，为什么两份测评差这么多

这是选悉尼 VPS 绕不过去的一段，也是资料里最容易把人带偏的地方。

一份第三方 Ping 测试给出的数字是：电信约 306 ms、联通约 284 ms、移动约 378 ms，港澳台及东南亚约 129 ms。另一份路由分析则说电信和联通回程走 Cogentco 经美西圣何塞中转，通常 200 ms 以上，移动回程走 NTT 转 CMI、经新加坡到香港回国，大约 170–180 ms。移动这一项，两份数据差了 200 ms，电信也不一致。

两份都没有标注具体的测试日期，也没有说明测试节点在哪个省、什么时段跑的。联通 284 ms 和移动 170 ms 可能都是真的，只是一个在凌晨测、一个在晚高峰测，或者一个测的是沿海省份、一个测的是内陆。所以诚实的说法是：**国内三网访问 Evoxt 悉尼大致落在 280–380 ms 这个区间，联通相对最好，移动波动最大**。任何给出单一确定数字的说法，都只是某一次测试的切片。

路由走向上两份资料是一致的：国内三网回程基本都要先去美西节点，再转回悉尼。联通去程 AS4837 直连圣何塞后接 Cogentco 到悉尼，移动回程走 NTT 转 CMI 经新加坡回国。这条路径不是 Evoxt 一家的选择，平价悉尼机房普遍如此，直连澳洲的海缆容量和成本摆在那儿。

稳定性方面，欧美和亚洲多个海外节点的测试基本无丢包；大陆电信、联通白天尚可，移动在晚高峰丢包会多一些。这个结论对建站很重要：如果你的访客是澳洲本地人或者东南亚用户，他们感受到的是本地延迟；如果你的访客在国内，他们感受到的就是那 300 ms。
